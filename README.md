# gakujin-mori-app

神山まるごと高専 基礎数学Ⅰ 後期第1回（三角比導入） — 「岳人の森」フィールドワーク用アプリのプロトタイプ

> 仕様の全体像: [full-spec.md](./full-spec.md)

## 現在のステータス：共有バックエンド稼働中（Google Apps Script + スプレッドシート）

クラス全員の測定データは **Google Apps ScriptのWeb App + Googleスプレッドシート** を
簡易DBとして共有している。写真以外の全フィールド（班名・対象物名・位置・距離・角度・高さ・気づき）が
端末をまたいで反映される（約12秒ごとにポーリングで自動更新）。

- コード: `appsscript-src/Code.gs`（doGet/doPost）。データ実体は初回実行時に自動作成されるスプレッドシート
  （Apps Scriptの実行者＝山本のGoogleドライブ内、「岳人の森 数学MAP データ」）
- フロント側は `src/api.js` が `VITE_SHEETS_API_URL` にPOST/GETするだけのシンプルな構成
- **写真は同期対象外**（端末内のみ）。Apps Scriptのセル容量・実装コストとのトレードオフとして意図的に外した
- 初回アクセス時、Apps Scriptのコールドスタートで反映まで数秒〜十数秒かかることがある
- オフライン時の自動リトライ・キューイングは未実装（送信は投げっぱなしでエラーは無視される）。電波が悪い場所では
  保存→MAP反映にタイムラグが出る前提で使うこと

### 本番投入前にやっておくとよいこと

1. 実際の授業直前に、テスト用に入れたダミーデータ（`PROD-CHECK`班など）をスプレッドシートから削除する
2. スプレッドシートのURLは `appsscript-src/Code.gs` の `setup()` をApps Scriptエディタで実行するとログに出る
3. 送信失敗時のリトライ・オフラインキューを入れる場合は `src/api.js` の `pushDiscovery` を拡張する

## ローカル開発

```bash
npm install
npm run dev
```

`VITE_SHEETS_API_URL` を `.env.local` に設定するとローカルでも共有MAPを確認できる（`.env.example` 参照）。
未設定の場合は自動的にlocalStorageのみのモック動作にフォールバックする。

## 画面構成

| 画面 | 内容 |
|------|------|
| オンボーディング | 班名・目線の高さを入力 |
| ホーム | 新しく測る／MAP／記録／今日のミッション／振り返り への導線 |
| 新しく測る | 対象物名・カテゴリー・写真・GPS・距離・角度を記録（高さは計算しない）。角度は手入力の他「角度センサー（目安）」で端末の傾きから概算できる |
| Discovery詳細 | 未解放時は「？？？」のみ表示。数値の修正も可能（修正すると計算済みの高さも自動再計算）。解放後にtan計算→結果と三角形の図解 |
| MAP | Leaflet地図上に自分の記録＋他班の記録（共有バックエンド経由）＋デモ見本データのピンを表示 |
| 記録一覧 | 自分の班のDiscovery一覧 |
| 振り返り | 授業終了時の自由記述（200字） |

数学解放はトップバーの🔒ボタン、またはDiscovery詳細の「🔓 数学を解放して計算する」から
ワンタップで解放できる（コード入力なし。目的は進行管理のみなので教員の合図で押す運用）。

